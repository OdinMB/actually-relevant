## 5. Text-marking feasibility assessment

- **What reaches people:** the story analysis (row 1), about 280 generated words per story on the story page, from OpenAI gpt-6-luna, free-form text of 200 tokens or more. The API and widget serve the same text; the newsletter is a composite of short generations. The podcast script (≥200 tokens, gpt-6-sol) counts only if it is published (q3).
- **Options considered** (fix-patterns §8; assessment 5.1):
  1. Move the `assess` tier to a model with an active text watermark (per [ANT] on 2026-09-25: Claude Fable 5.1, Mythos 5.1, Opus 5.5, Opus 5). Costs a higher per-call price than gpt-6-luna against today's spend of about $30–60/month (`StewardshipPage.tsx`), an Anthropic key, a second processor in the privacy notice and a DPA, and a prompt recalibration (the prompts were tuned for GPT-6 on 2026-09-24). Detection would be Anthropic's private-preview text detector (brief §10 q17).
  2. A third-party or post-hoc text watermark: legally envisaged [G ¶74; CoP 1.1.2], but no production-grade product for third-party model output was verified (UNCONFIRMED).
  3. This documented assessment and the gap analysis in §6: needed whatever is chosen, but documentation, not compliance.
  4. Wait for OpenAI: the goal is stated and tied to its Code commitments, with no date [OAI-HELP].
- **Chosen (owner, 2026-09-25): wait for OpenAI (option 4)**, with options 3 and the interim measures below. Never shorten, split or pad the analysis to get under 200 tokens.
- **Interim measures:** the visible labels in §3 and §7 (approved copy, implemented pending deploy), plus the machine-readable markers in §3 (API `aiGenerated`, story-page `data-ai-generated`, carousel XMP). These are **not equivalent to the Code's watermark layer**: they are unsigned, removable, and do not survive copying, screenshots or paraphrase.
- **Feasibility is objective**, not measured by this project's resources [G ¶81]. Text watermarking is on the market from another vendor (option 1), which weakens an infeasibility argument; implementation cost may be taken into account [G ¶85]. Under the strict reading of Art. 111(4) the gap is open now; under G ¶153 it must close by 2 Dec 2026.
- **Monitoring:** on **2026-11-15**, re-check OpenAI text provenance (https://developers.openai.com/api/docs/guides/content-provenance, https://help.openai.com/en/articles/8912793-provenance-signals-content-credentials-synthid-in-openai-generated-content) and Anthropic's per-model coverage (V3). If OpenAI text is still unmarked, bring option 1 back to the owner with a measured cost (eval harness on the fixtures, `eval:recalibrate`; spending is the owner's call) so a decision lands before 2 Dec 2026.

## 7. Label policy and correction channel

- **Copy (owner-approved 2026-09-25, label copy review ACR-1 to ACR-18):** website wording in `client/src/components/ai/aiDisclosureCopy.ts`; RSS, OpenAPI, newsletter, social, bio, podcast and carousel wording in `server/src/lib/aiLabelCopy.ts`. Change wording there, not at the call sites, and only with the owner's approval; the rendering tests assert the exact strings, so a wording change updates them too.
- **Components** (`client/src/components/ai/`): `AiBadge` (visible "AI", screen-reader name "AI-generated" by default, "Selected by AI" on quotes; takes its color from the surrounding text), `AiLabel` (decorative badge plus visible text, announced once), `SiteAiNotice` (`role="note"`, link to `/methodology`, no dismiss control), and `StoryTitleLabel` (badge plus title label, `client/src/components/`). Every public listing renders headlines through `StoryCard` or `StoryTitleLabel`; a new listing must too. The site's pages are English only (`<html lang="en">`), so no `lang`, `dir` or `<bdi>` handling is needed yet.
- **Where each label sits:** §3, one row per surface. The bottom sign-off "Curated with care by AI." (`BRAND.claimSupport`) stays next to the top notice.
- **Social account bios and bot flags (ACR-11, ACR-12), not applied yet:** `server/src/scripts/set-social-bot-profile.ts` sets both bios to "Automated account. Posts are generated by AI from {N} news sources. actuallyrelevant.news" (N = active feeds when it runs, the same count as `/api/sources`: 79 on 2026-09-25), sets Mastodon `bot=true`, and adds the `bot` self-label to the Bluesky profile record, keeping every other profile field. Dry run by default: `npm run social:bot-profile --prefix server`; to write: `npm run social:bot-profile:apply --prefix server`. It needs the production database URL and both accounts' credentials in `server/.env`; the Mastodon token needs `read:accounts` and `write:accounts`. Only the owner runs it (the accounts are theirs); nothing in the app changes the live profiles.
- **Machine-readable markers:** API `aiGenerated` (`withAiGeneratedMarker()`, applied in the public routes; `.context/public-website.md`); `data-ai-generated="<API field names>"` on the story page's AI regions; carousel XMP (`server/src/lib/xmp.ts`). When a new model-written field is added to `assessStory` and the public select, add it to `AI_GENERATED_STORY_FIELDS`; `analysis.test.ts` fails until you do. The registry lists `quote` and `quoteAttribution` because the model writes (and may translate) them; this is more conservative than assessment B1, which treats the extracted quote as outside Art. 50(2), and it means a republisher may label a verbatim quote from a named person as AI-generated (open item, §11).
- **How labels are checked:** a rendering test per surface asserts the exact text, the accessible name and that the label comes before the AI content it labels. On 2026-09-25 each mechanism was disabled once and its test went red, including the card and hero badge in `StoryTitleLabel` (14 tests in `StoryCard.test.tsx` and `HomePage.test.tsx`, run in the review). The prerendered static pages (`npm run build --prefix client`) were grepped for the top notice, the methodology and privacy lines and the author meta; the card, hero and quote labels need story data, so only the rendering tests cover them before deploy. A first-visit browser check (D3) belongs on each release.
- **Correction channel:** the feedback page (`/feedback`), invited on the methodology page ("Spotted AI content without a label, or a label that's wrong? Tell us on the feedback page."). Substantiated mislabelling is fixed without undue delay.
